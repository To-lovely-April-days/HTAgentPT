## 本批新增的规范（补进第一张已定的规范）

**密级三色的形态规则（本条归纳并取代上一批只针对琥珀的写法）**：

`#b3261e 机密` / `#8a5a00 内部` / `#00696b 公开` 三色在**徽标（pill）形态**下各自专表对应密级，
三者都不得被非密级语义借用——交付状态、工单状态、批注标记、「待确认」一类元数据徽标一律
用中性 `#eef1f5 / #5a6673 / #dde3ea`。反过来，非 pill 形态不受此限：红用于错误面板、失败图标、
危险按钮，琥珀用于警示面板与警示态按钮，都保留。

上一批只写死了琥珀一侧，结果本批在青绿那侧翻了车——页脚站级密级标识文案是「内部系统」，
却套了密级「公开」的青绿配方。归纳成三色通则后这类错误才被堵死。

**补充（第 8 批）**：非密级徽标默认用中性，这是缺省而非禁令。确需色彩区分时——例如
5.2.5 明确要求四种填充来源「以文字与颜色区分」——另取密级三色与强调色之外的色相，
并登记进色板，不得回头借用密级三色。已据此新增紫色一档：

`#8f3d74 / #fbeff7 / #edd2e3`　语义为**待人工确认的未决状态**。目前用于方案生成中的
「AI 建议待确认」。它不参与密级形态规则，因为它不是密级。

**这一档最初取的是紫色 `#6b4fbb`，被色彩验证器否掉了**：它与强调蓝 `#2f5ccc` 在正常
视觉下 ΔE 仅 8.3，低于 15 的硬性下限——即使色觉正常的人也难以区分，而 A6 里这两色
正是四种填充来源之间的分类对比。改用品红后色盲下 ΔE 14.9、正常视觉 20.0，全部通过。

核验命令（dataviz 技能自带）：
`node scripts/validate_palette.js "#2f5ccc,#8f3d74" --mode light`

站级密级标识（`site.classification_label`）本身就是密级标识，用对应密级的 pill 是正确的，
不属于「非密级语义借用」。

**配置项透视徽标**：沿用密级徽标几何（h19 / padding 0 6 / radius 3 / 11px / weight 500），
但用中性配色（底 `#ffffff`、描边 `#cfd6df`、文字 `#5a6673`、键名 IBM Plex Mono）。
绝不借用密级三色与强调色 `#2f5ccc`，否则与密级徽标和强调色语义相撞。

部署期与运行期两档**靠填充而非色相**区分：部署期实底 `#eef1f5`，运行期描边 `#cfd6df` 白底，
文字同为 `#5a6673`。不得把载体档位绑在 `theme.accent` 上——那会让同一枚元数据标签在不同
公司呈现不同颜色，读者会误以为颜色在表达状态差异。

**客户侧显式例外**（K 组界面，二期转小程序）：已定的控件高 24/26/28/32 与字号 11/12/12.5
是为桌面密集信息设计的，客户侧须另立一套——可点区域最小 44×44，输入框字号不低于 16px
（低于 16 会触发 iOS 聚焦自动放大导致布局错位），正文 15，主按钮高 44。顶栏 48、密级徽标 19
在客户侧不出现。这是对既定规范的公开例外，不是私自改规范。

## 登录页的配置项清单

10.4 判定标准是「在一台全新服务器上部署后，除填写配置外不需要修改任何代码即可运行」。
登录页是公司标识最集中的地方，以下七项一律不得硬编码。原型内建「配置项透视」开关
（默认关闭）可视化这些位置，并提供「切换公司」演示同一份 DOM 换一组配置的效果。

| 键 | 载体 | 说明 |
|---|---|---|
| `org.logo` | 部署期 | 图形标识 |
| `org.display_name` | 部署期 | 公司全称，页面主标题与页脚 |
| `app.display_name` | 部署期 | 系统名 |
| `theme.accent` | 部署期 | 强调色，默认 `#2f5ccc` |
| `auth.notice` | 运行期 | 接入方式说明文案 |
| `auth.support_contact` | 运行期 | 管理员联系方式 |
| `site.classification_label` | 运行期 | 页脚密级标识文案 |

部署期＝配置文件，改动需重新部署；运行期＝数据库配置项，管理界面可改、即时生效（FR-9.6）。

**异常态文案不得出现实现选型字样**——不得写「Qwen 无响应」「MinerU 解析失败」「vLLM 超时」
「蒲公英未连接」，也不得出现 pgvector、向量库等组件名，不得暴露服务地址、端口、容器名。
只用能力名：「对话模型服务」「检索服务」「文档解析服务」，且能力名本身也是配置项文案
（8.2 末段要求换引擎不改业务代码，名称可能随之变化）。

## 生产实现须注意

原型从 `fonts.googleapis.com` 取 IBM Plex，**仅为演示**。10.2 要求数据不出域、内网区不开放
公网出口，内网服务器拉不到公网字体——生产实现必须随交付包自托管（SIL OFL，可商用）。
同理不得引入任何 CDN 脚本、第三方验证码（登录页最易被塞入 reCAPTCHA 一类）、
前端错误上报 SDK、埋点统计。中文回退栈需同时覆盖 Windows（微软雅黑/思源黑体）、
macOS（PingFang SC）、Android（Noto Sans CJK）与微信内核。

## 本批刻意没画的状态

需求扫描挖出下列状态确实需要界面，但超出「C1 登录 + C4 服务不可用/无权限」的范围，
按量小收口留到后面排期。列在这里以免遗漏：

| # | 状态 | 依据 / 性质 |
|---|---|---|
| 2 | 会话失效就地重登模态（令牌过期） | 接口以 JSON 返回拒绝而非 302，故就地模态而非整页跳转。文案须是「内容仍在页面上（未丢失）」+「尚未保存到服务器，重登后请立即保存草稿」，绝不可写「已自动保存」 |
| 3 | 账号已停用（整页，不提供就地重登） | FR-7.1 停用后立即失去全部访问权。与 2 必须分开：一个可重登、一个重登也没用 |
| 4 | 该账号已在其他终端登录 | **已定为互斥。**需两个界面：C1 的登录拒绝态（与口令错误分开），以及 C4 的会话终止态「本账号已在其他终端登录，本终端会话已结束」——后者可重登，但重登会反向踢出对方，动作与文案都与令牌过期、账号停用不同 |
| 5 | 尚未指派角色 | 账号已建但未指派角色时登录成功却无可落地工作台，不能落到空白页 |
| 6 | 网络不可达（远程 VPN 掉线） | 前端拿不到任何响应。**不得误报为「服务不可用」**，那会引发无谓运维工单 |
| 7 | 浏览器版本不受支持 | C1 之前就可能出现的整页降级 |
| 8 | 客户入口的登录与异常态 | 隔离区、手机优先，与内网**两套独立构建产物**。共用会把内网路由表、角色名、内部接口路径打包进隔离区资源，属可读出的信息泄露 |

另有「文档解析服务不可用」的等待态，归属管理后台解析任务队列（E3），不在本批。

## 已确认的四条决策（2026-09 需求方拍板）

| # | 决策 | 落地影响 |
|---|---|---|
| 1 | **管理后台功能项七项**，审核台归总部审核人变体 | 左栏 = 后台首页 + 七项；审核台只在总部节点的审核人变体里出现 |
| 2 | **不做自助改密**，用户菜单五项 | 见下方连带后果 |
| 3 | **管理员落地页 = 带告警条的后台首页** | 新增一页（表 9-1 无此页），见界面清单 E0 |
| 4 | **同账号多终端互斥** | 待画状态表第 4 项由「待拍板」转为「已定义」，需两个界面 |

### 决策 2 的连带后果

用户没有任何改密能力，于是：

1. **「首次登录强制改密」随之取消**——它依赖用户能自己设口令。已从待画状态表移除。
2. **E14 用户与权限必须有「重置口令」动作**，否则口令一经下发永远无法更换。
   该动作属权限相关操作，须进审计（FR-9.1）。
3. 净效果是管理员长期知悉全员口令。这一点界面上补不了，只能靠制度（下发后立即轮换、
   定期强制重置）补偿。记录在此以免日后被当成设计疏漏。
