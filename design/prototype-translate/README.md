## 最容易漏的是 FR-6.3 的最后半句

原文：「回填范围包含正文、表格单元格、页眉页脚与文本框；**无法回填的元素在结果中列出**」。

前半句人人都读到了，后半句常被跳过。不列出来，用户会以为整份都译了，直到客户指着
图里的英文问为什么。D1 右栏专门有一块，逐条给出位置、类型与原因：

| 类型 | 为什么回填不了 |
|---|---|
| 图片内文字 | 文字嵌在位图里，没有可替换的文本层 |
| 公式对象 | OMML 公式整体不参与回填，其中的变量说明未译 |
| 页眉自动编号域 | 域代码打开时才求值，回填会破坏编号 |

这三类是 Word 回填的固定难点，不是本项目特有的——实现时几乎必然会碰到，提前在界面上
留好位置，比事后补一个提示框好。

## 术语注入要看得见

FR-6.1 要求命中的术语以强制对照形式写入提示词。但光做不显，用户无从判断译名对不对。
D1 正文里把命中术语标出来，右栏列出「全文 N 处，译法一致」——判定标准 M6 第一句
「同一设备名称在全文译法一致」就是靠这个自证。

## 术语表有两个下游

改一条术语会同时影响两处：

- **翻译**（FR-6.1）以强制对照注入提示词，保证同一设备全文译名一致
- **问答**（FR-4.2）把命中的同义表述注入查询改写，扩充召回

E10 界面底部写明了这件事。改的人如果只想着翻译，可能会把一个对检索很有用的同义表述删掉。

## 提交术语不会改写本次译文

D2 的弹层里明写了这一条。FR-6.4 是「提交补充至术语表，经管理员确认后生效」——
生效指的是**从下一次翻译起**。本次译文要用新译法，得手工改。

不写清楚的话，用户提交完会以为译文已经跟着变了，拿去用才发现没变。

## 分批与合同提示

- **分批**（FR-6.2）：切到「翻译中」可看进度。界面上注明按段落边界切分、不在句中断开，
  单批长度可配置——10.1 明确翻译长度不设硬上限，靠分批处理。
- **合同类**（FR-6.6）：切到「合同」会出现人工复核提示，并注明该提示同时写入下载文件的
  页眉。只在屏幕上提示而不写进文件，文件一转手提示就没了。
