## 对着判定标准画的三处

**表格必须仍是表格。** 表 11-1 对 M1 的判定原文是「分块检视中表格未散架、章节标题保留、
页码可回跳原文」。所以 #12 特意做成一个含表格的分块——表格在分块卡片里仍渲染为表格，
不是被拆散的文本行。这是解析质量最容易出问题、也最容易在界面上被掩盖的地方：
把表格降级成纯文本后界面看起来照样"正常"，检索时却永远命中不到表头。

**重叠区默认显示。** 所有切分策略统一保留相邻块之间的重叠，默认块长一成。若不显示，
用户会把相邻块开头的重复文字当成解析出错而去手工删掉——而它恰恰是防止答案落在切分
边界被截断的机制。显示出来并注明"与 #11 重叠 38 字"，这个误会才不会发生。

**失败不得只写「失败」。** FR-1.7 点名四类原因：文件损坏、格式不支持、超时、引擎异常。
E20 四类的具体信息、失败环节、可采取的动作与主按钮全部不同：

| 原因 | 主按钮 | 为什么不同 |
|---|---|---|
| 文件损坏 | 重新上传 | 已读到的前 13 页不予保留——部分入库会让检索结果缺页而无从察觉 |
| 格式不支持 | 仅登记元数据 | 图纸解析属二期。文件仍留存，只是不进分块与向量化 |
| 超时 | 调整时限后重试 | 建议先拆分。整本汇编切出的分块跨主题，相关度本来就会偏低 |
| 引擎异常 | 换策略重新解析 | 已达重试上限。换「按语义段落」可绕过表格识别，代价是表格被拆成文本行 |

## 两处刻意的边界

**引擎不可达不进这个弹层。** 10.3 要求「解析引擎或模型服务不可用时将任务置于等待而非
失败」。所以进 E20 的只有"引擎接收了任务但处理出错"；引擎整体不可达是队列里的等待态，
属 E3 解析任务队列，不是失败。

**重新解析会丢手工编辑。** FR-1.5 允许逐块手工编辑且只重算该块向量，FR-1.6 的重新解析
则作废全部原分块。两者叠加的后果是：手工修过的块会在重新解析时一并丢失。E19 的警告条
明确写出了「其中 3 块的手工编辑将一并丢失」——只写"原分块作废"不足以让人意识到这件事。
