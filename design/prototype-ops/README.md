## 这一批想清楚的几件事

### 1. H 组不是管理后台的一个视角，是另一个节点

3.4 第一条把公司隔离定为架构级约束。若审核台做成管理后台里的一个角色变体，那这个角色就存在于某一家公司的部署里，而它要看的是集团共享库——路径上就说不通。

所以 H 组的顶栏公司位写「集团共享库 · 总部节点」而不是公司名，标识块用中性灰 `#5a6673` 而非公司强调蓝，左栏只有审核台 / 共享库问答 / 公开库发布三项，并在左栏底部明写：**各公司私有库不存在访问通道——不是权限没给，是架构上就没有这条路。**

同一份代码，换一组配置渲染。

### 2. 相关度是机器给的，重复是人判的

H3 检索出的四条相关度都在 0.71 以上，因为同型号同报警代码的故障现象本来就写得像。照相关度一键判重，留下的会是最先入库那条而不是成因覆盖最全那条。

界面上的落点：**没有「判为重复」快捷按钮，只有逐项对照。** 对照表逐字段标「相同 / 不同」，成因与处理步骤不同的两条都留。FR-8.6 说的是检索结果里归并展示，不是合并成一条。

判为重复时，对照记录作为附件随驳回原因回传给提交人——让他看到是跟哪一条重的。

### 3. 「我已知悉」不撤告警

FR-9.3 写死「任务失败须告警，不得仅写日志」。若点一下就能清掉告警，这条需求等于没实现——那只是把日志换了个地方写。

E0 的处理：「我已知悉」写一条审计并在告警条内追加一行「已知悉 · 陈工 · 09-14 09:14」，**告警条本身保持显示**，要等异地备份真正跑成功一次才撤。首屏那句话直接写给用户看。

首屏其余部分只放「不处理就会一直卡着」的东西：待解析、解析失败、待补元数据、待审定条款、待指派角色。

### 4. 换向量化模型必须连带全量重建

这是整份 PRD 里最容易被实现漏掉的一条。新旧向量不在同一个空间，拿新问题去比旧向量，算出来的相关度是个没有意义的数——**检索会持续返回错的结果，而且不报错**。

E15 的落点有三处：向量化模型那一项单独用琥珀底圈出；写明重建时长（6.5 小时）与期间降级方式；页底常驻一行「与当前模型不一致的分块 = 0」。最后这一行是长期哨兵，不能只写在日志里。

### 5. 阈值不是能照抄的数

4.3 明写「重排分值非标定值，阈值须在试运行期间以真实问题集标定」。

所以 E15 的阈值旁边挂的不是「推荐值 0.6」，而是**标定记录**：问题集名称与题量、命中率、误拦率、错答率、上次标定日期。改了阈值不重标，就给出「按上次标定分布推算，调到 0.75 会多拦 31 题，其中 22 题原本答对」——把代价说成人话。

### 6. 把「没备份什么」写在界面上

10.3 说向量索引可由原始文件重建、不纳入常规备份。这是对的，但只写在文档里不够——灾难恢复当天会有人以为「备份都恢复完了怎么搜不出东西」是系统坏了。

E16 把覆盖范围做成四张卡：三张绿的（原始文件 162 GB / 业务库 21 GB / 配置项 8 MB）加一张灰的（向量索引 46 GB），灰卡上直接写「不备份，恢复后需重建约 6.5 小时」。

### 7. 「无结果比例」不是故障率

阈值拦截是设计要的行为。把这个比例配红箭头当错误率看，是读反了需求。

E18 把它落成「本周返回未找到的问题」清单，每行带一列「库里缺什么」，处置分四类：待补语料 / 已通知 / 非缺口（权限不够，不是缺口）/ 范围外（供应链数据不在本系统内）。图下那段话写明：继续压这个数只有两条路，调低阈值放行低相关的答案，或者真把语料补上——**前者是把问题藏起来**。

### 8. C3 要把「做不到的事」明确写出来

决策 2 定了不做自助改密。个人中心若只是把改密入口删掉，这一页看上去就像没做完。

反过来写：标明「不可自助修改」、说清找谁重置（管理员陈工）、摆出上次重置的时间与经手人——重置本身进审计。

操作记录与 FR-7.5 是同一份数据：离职回收时管理员导出的那一份，和本人在这里导出的那一份，**字段必须完全一致**。两边不一致，离职交接当天就会有人拿两份对不上的表来吵。被拒的越权请求也留在表里并写明当时申请的是什么——不是留污点，是免得日后争执「我明明打开过」。

## E18 的图表决策（可视化规范）

**六个模块做成六张小图，而不是六条线挤一张图。**

直接原因是色相预算。本系统的密级三色（机密红 `#b3261e` / 内部琥珀 `#8a5a00` / 公开青绿 `#00696b`）加状态绿 `#1c6b45`、强调蓝 `#2f5ccc`、待确认品红 `#8f3d74` 已经占掉色相环大半，再凑六个彼此可分、且不与密级撞义的分类色，凑不出来。

小图每张只有一条序列，一个颜色就够——**本页因此完全不需要分类色板**。顺带也避开了双轴：命中率与无结果比例量纲相同，仍然分成两张图，因为它们不是同一件事的两面。

其余落点：
- 柱用 `border-radius: 3px 3px 0 0` 贴基线，柱间 3px 让底色透出来
- 折线 2px，数据点 r=4（末点 r=5.5 加白描边），末点直接标数值，不是每点都标
- 深浅只表示时间远近（本周 `#2f5ccc` / 此前七周 `#b9c9ee`），**不表示分类**——这一句写在图注里
- 柱与点都带 `title` 悬停提示；顶栏有「图 / 数据表」切换，数据表列出每个点的原始数值，与导出的 CSV 一致

调色板校验（在 dataviz 技能目录下执行）：

```
node scripts/validate_palette.js "#2f5ccc,#1c6b45" --mode light
```

结果：CVD 分离 ΔE 21.7、常视 ΔE 23.2、对比度均过——但 `#1c6b45` 触发「色度低于下限（读起来发灰）」。该项只约束**分类色板**，而这两色在本系统里是强调色与状态色，且状态色一律带文字标签，不靠颜色单独表意。E18 本身不含任何分类序列，故不适用。
