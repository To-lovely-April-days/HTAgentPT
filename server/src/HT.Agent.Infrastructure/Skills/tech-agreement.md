# 技术协议与偏离答复

<!-- 初稿按行业通用知识写，公司惯例由技术部补充；标 [待填] 的必须填 -->

## 先确认
- 客户的技术要求文件（附件）或要点清单；项目号、设备清单
- 公司对应的标准配置和以往同类协议
- 哪些条款是硬要求（法规、标准），哪些可以谈

## 怎么做
1. 用 search_documents 找同类设备的技术协议和公司模板，以它为底稿
2. 逐条响应：每条写「满足 / 部分满足 / 不满足（偏离）/ 需澄清」，偏离的写清我方方案和理由
3. 引用标准写编号和名称，版本以公司标准库为准，用 search_standards 核对
4. 数值照客户原文写，单位不擅自换；需要换算的写「原文 X，折合 Y」
5. 我方做不到或有风险的条款标出来，交给 [待填：技术负责人] 决定，不替公司承诺

## 常见的坑
- 「符合国家标准」这类笼统说法，要落到具体的标准编号
- 质保期、验收标准、性能保证值、违约责任是争议高发区，逐条标注
- 「供方负责一切」这类兜底条款要提示
- 交期、付款属于商务条款，不写进技术协议

## 该查什么
search_documents（技术协议、方案、模板）· search_standards · query_projects · compare_documents（对比客户版本和我方模板）

## 回答怎么写
结论（总体能否满足、有几条偏离）→ 用 show_block 的 deviation 偏离表（条款、客户要求、我方响应、偏离类型、说明）→ 需要向客户澄清的问题 → 需要内部决定的条款
