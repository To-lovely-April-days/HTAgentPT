# 前端（React）

企业内部智能体系统的 Web 前端。对应 `design/` 下的高保真原型——原型即实现规格，页面结构、
文案、间距、配色都以原型为准；对应后端见 `server/`（本地默认 `http://127.0.0.1:5210`）。

## 技术栈

- Vite + React 18 + TypeScript（严格模式，`erasableSyntaxOnly`）
- react-router-dom（路由）、@tanstack/react-query（服务端状态）
- 不引 UI 组件库：`src/styles/global.css` 复刻原型的设计令牌与公共类
  （`--accent` 主蓝、密级三色 pill、48px 顶栏、240 左栏、360 来源栏等）
- SSE 用 fetch + ReadableStream 手解（`src/lib/api.ts` 的 `sse()`），POST 携带体

## 运行

```bash
pnpm install
pnpm dev        # http://127.0.0.1:5173，/api 代理到 127.0.0.1:5210
pnpm build      # tsc -b && vite build
```

先按 `server/README.md` 起后端（PostgreSQL + 公司节点 :5210），再起前端。

## 第 1 批要点

- **登录（C1）**：错误按后端原因码逐条呈现（口令错误/账号停用/终端未绑定），不提供自助改密，
  提示联系管理员重置；`supersededOther` 时先给「另一处会话已被终止」的过渡页再进工作台（决策 4）。
- **框架（C2）**：导航按角色 + 权限双重过滤（售前/售后/总部审核/管理员/客户各自的导航组），
  顶栏常驻可访问密级 pill；总部审核角色带「集团」灰标。
- **会话互斥（决策 4）**：终端标识首次生成后存 localStorage；任一请求返回
  `SESSION_SUPERSEDED` / `SESSION_EXPIRED` / `ACCOUNT_DISABLED` 即清令牌回登录页，
  并在登录页明示被下线的具体原因，不笼统说「过期」。
- **问答（A1）**：SSE 全事件接入——`meta`（意图/改写/降级提示）、`delta` 流式增量、
  `sources` 右栏来源（密级 pill + 得分 + 章节页码 + 原件下载）、`no_result` 如实说没有并列
  可能相关文档、`table` 台账结构化表格（金额列按权限隐显）、`redirect` 转生成/翻译、
  `error` 流中错误。台账/转向均带「不是这个意思？按知识问答回答」纠偏重问（forcedIntent）。
- **未接入页**：占位页标明「服务端能力已就绪」与对应接口，后续批次逐页替换。

## 第 2 批要点

- **A2 项目查询**：结构化查询（客户模糊/年份/受控词表设备类型/交付状态/金额区间），
  「与」关系；无结果态与问答的阈值拦截刻意不同——回显当前条件、点 ✕ 去掉重查，
  没有「可能相关」。命中行点击进详情；导出 CSV（公式注入已防）。
- **字段级密级双层裁剪（M7）**：无机密权限的角色，金额列与金额筛选项都不渲染
  （只藏列不藏筛选等于留反推通道）；详情页合同金额整行消失，不打码不置灰；
  机密文档整条不出现且不报数量。可见性判定与服务端同一条规则，裁剪本身在服务层。
- **A3 项目详情**：左台账字段 + 右关联文档（类别/密级 pill，点卡片带鉴权下载原件）；
  「就本项目提问」跳问答并预填客户/设备/年份筛选；面包屑如实反映来路
  （售后经问答台账点行到达时是「问答 › 台账查询结果 › 项目详情」）。
- **下载修复**：/api/files 需要鉴权头，普通链接带不上——统一改为 fetch + blob 触发保存，
  A1 来源栏的「下载原件」一并修正。

## 第 3 批要点

- **B2 案例检索**：同型归并（FR-8.6）——按设备型号分组，每组先给 3 条其余折叠展开，
  组头拆分「本公司 N 条 · 共享库 N 条」；相关度/时间双排序；本公司案例带流转状态 pill，
  共享库案例带来源公司 pill。
- **B3 案例详情**：四态流转时间线（local/pending/shared/rejected）+ 各态主动作：
  提交总部（先走敏感检测，有命中先呈现并在正文就地高亮，确认无泄漏才提交）、
  撤回提交（真链路：先撤总部待审副本，成功才本地回退）、驳回原因展示 + 修改后重新提交。
  常驻说明「录入即生效，不依赖审核」。
- **B4 案例录入/编辑**：七个结构化字段表单；右栏「保存后会发生什么」讲清一条案例
  同时是结构化行 + 语义分块两样东西；输入型号即联想「同型号已有案例」防重复录入。
- **后端配套**：新增撤回提交链路（公司 POST /api/cases/{id}/withdraw → 总部同步通道
  撤下待审副本，已有结论则拒绝）；同型归并组补本公司/共享库计数拆分。

## 第 4 批要点

- **D1 翻译**：文本 / 文档（docx）双模式，方向与术语域可选。三条最容易做丢的需求
  在界面上自证——命中术语正文标记 + 右栏「以强制对照写入提示词」（FR-6.1/M6）、
  无法回填元素逐条列出（FR-6.3 末句，不许静默）、合同类识别提示条并注明同时写入
  下载文件页眉（FR-6.6）。docx 结果给回填报告（段落总数/已译出/无法回填）与带鉴权下载。
- **D2 术语修正提交**：从命中术语的「译法不当」进入；修正的是译入语一侧；界面写死
  「本次译文不会自动改写，管理员确认后从下一次翻译起生效」，并说明术语表同时供
  问答检索改写使用。提交后进管理后台待确认列表。
